How Survivor War Room works

Every recommendation this app makes is built from live, free public data — no paid AI model, no black box. This page explains exactly what's being pulled, in what order, and how it turns into a ranked list of picks.

Data sources

Everything below is fetched fresh, directly from your browser, each time you click "Pull live data" or "Refresh live data"
The Odds API PRIMARY ODDS
A multi-sportsbook consensus moneyline. The app requests head-to-head (h2h) American-odds prices from every book The Odds API reports for a matchup, averages them, and converts the average into an implied win probability. This call goes through a private Netlify Function so the API key never reaches your browser.
api.the-odds-api.com/v4/sports/americanfootball_nfl/odds — proxied via /.netlify/functions/odds
SportsGameOdds PRIMARY ODDS
A second, independent multi-sportsbook consensus, covering nine books (FanDuel, DraftKings, BetMGM, Caesars, ESPN BET, Bovada, Unibet, PointsBet, William Hill). It returns a "fair odds" value per side with the sportsbook's vig already removed — the app doesn't have to compute that itself the way it does for The Odds API. When both this and The Odds API have a line for the same game, their two probabilities are averaged together for a broader, more independent consensus than either source alone. Also proxied through a private Netlify Function.
api.sportsgameodds.com/v2/events — proxied via /.netlify/functions/sportsgameodds
ESPN Scoreboard & Odds FALLBACK ODDS
Used whenever The Odds API doesn't have a matchup yet (or is unreachable). ESPN's public scoreboard returns each week's matchups, kickoff times, unique event IDs, and — when posted — a single sportsbook's moneyline and point spread for the game.
site.api.espn.com/apis/site/v2/sports/football/nfl/scoreboard
ESPN Predictor (FPI) FALLBACK ODDS + POWER SCORE
ESPN's own Football Power Index-based pregame win projection. Sportsbooks don't post lines for games more than a couple of weeks out, but ESPN's predictor computes a projection for essentially any scheduled game on the calendar. It fills gaps in the odds priority chain below, and it's also the 60% component of the weighted Power Score used for the season-long future-outlook comparison.
sports.core.api.espn.com/.../events/{id}/competitions/{id}/predictor
nfelo POWER SCORE
An Elo-derived power rating per team, published as a public CSV by the open-source nfelo project (built on 538's Elo framework, adapted for the NFL). Updated by their own model pipeline each week. This is the 20% component of the weighted Power Score — see below for how it's combined with FPI and PFN's consensus rank and converted into a win probability.
raw.githubusercontent.com/greerreNFL/nfelo/main/output_data/elo_snapshot.csv
Pro Football Network Consensus Rankings POWER SCORE
PFN's own weekly power ranking already blends five outlets — PFSN, ESPN, NFL.com, CBS Sports, and FOX Sports — into a single average rank per team. Rather than a fragile HTML/markdown scrape, the app's Netlify Function reads the page's own server-rendered Next.js data (a JSON payload the page embeds for itself, containing each team's average rank) and re-publishes just the numbers as clean JSON. No API key, no third-party scraping service, no page-layout parsing to break. This is the 20% component of the weighted Power Score.
profootballnetwork.com/power-rankings-nfl — proxied via /.netlify/functions/pfn-rankings
ESPN Game Summary (Injuries)
For each of the week's top candidates, the app pulls that specific game's injury report and keeps only quarterbacks, running backs, wide receivers, and tight ends whose status isn't "Probable" — the positions and designations most likely to swing a game's outcome.
site.api.espn.com/apis/site/v2/sports/football/nfl/summary?event={id}
Open-Meteo (Weather)
Hourly forecast — temperature, precipitation chance, and wind speed — for the home stadium's coordinates, matched to the closest hour to kickoff. Skipped entirely for the 12 NFL stadiums with a dome or fixed roof. Forecasts only exist inside roughly a 15-day window before kickoff; outside that window the app says so rather than guessing.
api.open-meteo.com/v1/forecast

How a win probability is chosen

For every team in every matchup, the app tries each source in order and stops at the first one that has real data
1. Odds API + SportsGameOdds (blended)
→
2. ESPN moneyline
→
3. ESPN posted spread
→
4. ESPN Predictor (FPI)

Step 1 draws on both consensus sources. The Odds API returns raw per-book prices, which the app averages, then removes the sportsbook's built-in vig by normalizing both teams' probabilities so they sum to exactly 100%:

impliedProb(moneyline) = moneyline < 0 ? -moneyline / (-moneyline + 100) : 100 / (moneyline + 100)
// then, with both teams' raw implied probabilities:
fairProb(team) = impliedProb(team) / (impliedProb(home) + impliedProb(away))

SportsGameOdds already returns a vig-free "fair odds" price per side, so the app only re-normalizes it as a safety check. When both sources have a line for the same game, their two fair probabilities are simply averaged — the pick's odds source then reads something like "18-book blended consensus" (9 books from each source). When only one source has the game, that one is used alone.

Step 2 and 3 apply when neither consensus source has posted a line yet. ESPN's own scoreboard sometimes carries a single book's moneyline or spread even before the two consensus sources do; a spread is converted to a probability with a standard logistic curve:

homeWinProb = 1 / (1 + 10-spread / 14)

Step 4 is used when nothing has been posted anywhere — most commonly for games several weeks in the future. ESPN's Predictor already returns a clean win-probability percentage per team, so it's used as-is.

The weighted Power Score

A second, independent estimate — blending power-rating models instead of market odds — used specifically to compare a team's value across the season

Market odds (the priority chain above) are the best available read on this week's game. But they don't exist yet for games several weeks out, and even when they do, mixing "real odds this week" with "a model's guess for week 10" makes for an unfair comparison when deciding whether to save a team. To compare a team's value across its entire remaining schedule on equal footing, the app instead uses one consistent blended model for every week — the Power Score — computed under whichever formula is currently selected in the header toggle.

Yalango DEFAULT
The original 60/20/20 design behind this feature: 60% ESPN FPI, 20% nfelo, 20% PFN's consensus rank.
powerScore(home) = 0.6 × FPI(home) + 0.2 × nfeloWinProb(home) + 0.2 × pfnRankWinProb(home)
No Vibes
The market-model-only formula this app briefly ran as its only option, before PFN's consensus rank became scrapable — no media-consensus input at all, just the two model-derived sources.
powerScore(home) = 0.75 × FPI(home) + 0.25 × nfeloWinProb(home)

Yalango's 60/20/20 split briefly ran as 75/25 (FPI/nfelo only, now preserved as the "No Vibes" option) after CBS, The Athletic, and ESPN's editorial power rankings — the media sources originally slated for that third 20% slice — turned out to have no public API, be fully paywalled, or require fragile page-scraping that breaks whenever the article format changes. Pro Football Network's consensus ranking fills that slot instead in Yalango: its own page already blends five outlets into one number per team, and — unlike those other sources — it publishes that number as structured data the page embeds for its own use, not just as prose.

Switching models clears any already-pulled weekly analysis, since every Power Score number would change — pull live data again after switching to see numbers under the new model.

nfelo's rating isn't a win probability by itself — it's an Elo-style score, so it's converted using the standard Elo win-probability formula, with an assumed home-field advantage of 48 Elo points (a commonly cited estimate in Elo-based NFL models):

nfeloWinProb(home) = 1 / (1 + 10(nfeloAway − (nfeloHome + 48)) / 400)

PFN's consensus rank (1 = best, 32 = worst) isn't a win probability either, so it's first converted into a synthetic Elo-style rating — 14 points per rank position, an estimate rather than a published constant — and then run through the exact same logistic formula above, with the same 48-point home-field assumption, for consistency with the nfelo conversion:

pfnRankWinProb(home) = nfeloWinProb( (33 − pfnRankHome) × 14, (33 − pfnRankAway) × 14 )

If any source the selected model uses is unavailable for a given game, the Power Score redistributes weight proportionally across whichever sources are available rather than guessing. The Power Score is shown on every one of the week's top-5 picks alongside the market-odds win probability, so you can see where the two agree or disagree.

Building the weekly recommendation list

  1. Pull that week's full matchup list from the season schedule.
  2. Resolve a win probability for every team in every matchup using the priority chain above.
  3. Remove any team already marked "used" in your tracker — a used team can never be recommended again.
  4. Sort every remaining team, across every game that week, by win probability — highest first — and keep the top 5.
  5. For each of those 5, attach injury notes, a weather read, and a future-outlook note (below).
  6. The single highest-probability team becomes the top recommendation (or the top two, for a double-pick week).

The "consider saving" future-outlook check

A high win probability this week doesn't automatically mean a team is the right pick this week — if that same team is an even bigger favorite three weeks from now, burning it early can cost you later, since each team can only be picked once all season. To catch this, every one of the week's top-5 candidates is checked against the rest of its own schedule, using the Power Score (not market odds) for every week so the comparison stays apples-to-apples:

  1. Compute the candidate's own Power Score for the current week.
  2. Compute the Power Score for every remaining week on that team's schedule (skipping byes), and keep the single best one.
  3. If that future week's Power Score is more than 5 percentage points higher than the current week's, the pick is flagged "Consider saving" with the specific week and opponent named.
  4. Otherwise, the app simply shows the team's best remaining spot for reference.

This is a per-team comparison, not a full season-long optimizer — it tells you when a specific candidate has a better spot coming up, not the single globally-optimal order to burn all 32 teams across 18 weeks.

What this app doesn't do

  • No large language model, no AI-generated analysis, and no paid API calls are involved in scoring picks — every number above comes from a documented formula run in your own browser.
  • It doesn't optimize your entire season's pick sequence at once — the future-outlook check compares a team against its own future weeks, but it isn't a full season-long solver.
  • It doesn't account for game script, weather beyond kickoff-hour conditions, or breaking news between when you check and when you lock a pick — always double-check injury designations right before kickoff.
  • Your picks, used-team tracker, and pulled analysis are shared with everyone using the app, stored in a small database behind a private Netlify Function — this is a single shared pool, not per-person data. Your browser also keeps a local copy as a same-device fallback for whenever that connection is briefly unavailable.
This is a strategy aid built on free, publicly available sports data — it is not a guarantee of any outcome. Always verify injury designations and weather close to kickoff before locking a pick.
